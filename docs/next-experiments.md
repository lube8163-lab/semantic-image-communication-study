# 次段階の実験候補と判断

## 初期結果からの判断

特徴抽出自体は動くが、既存PiTヘッドに最終トークンを渡すだけでは元画像を十分に戻せない。追加の小画像を送っても、今回の凍結ヘッドは小画像だけの忠実性を改善しなかった。量子化だけを調整して有効な通信方式になるという根拠は得られていない。

## E002b: 既存特徴を使った追加の対照実験

追加学習の前に、既に保存したsigma=0.5/0.9の特徴でも同じ受信実験を行う。特徴のzero/shuffleと、受信側だけで決まる固定の出力正規化を比較し、入力noisy RGB・flowのスキップ・特徴条件の寄与を分ける。元画像を参照して画像ごとに後処理を最適化しない。sigma=0.1の失敗結果は残す。新しい重みの取得は不要で、既存の抽出済み特徴を使える。この対照実験はまだ実施していない。

## E003候補A: コンパクト特徴の情報を分けて測る

REPA付近の10層と最終24層を候補とし、trainだけで次元削減を学習する。既知の色・形・数・配置を1要因ずつ変えた制御画像と、ライセンス確認済みの未使用写真を分ける。意味保存の評価とピクセル復元の評価を別にする。

少ない容量の特徴から軽量な画像復号器を学習し、特徴のzero/shuffle、同容量の小画像・通常コーデック、認識モデル特徴との比較を置く。この復号器の実験は、Irisを条件付けて生成できた証拠とは区別する。train/evalの元画像を分離し、同じ画像の切り出しを別分割へ置かない。

## E003候補B: 特徴条件Adapter

Iris全体を凍結し、受信した圧縮特徴を新しいノイズからの生成へつなぐ小さいAdapterを検討する。noisy RGBへの原画像アクセスを復活させて成功扱いにしない。必要なseed、テキスト、補助画像、残差、条件トークンは全てパケットへ含める。

本格学習の前に、1バッチでの勾配計算・GPUメモリを測る。学習時間は初期forwardの0.15秒から安易に外挿しない。パラメータ数、更新する範囲、必要な画像枚数とモデル共有コストを確定してから判断する。

## 優先する小さい次の区切り

最初はE002bで復号条件の寄与を分け、その後、候補Aの情報量・復号可能性を測る設計を具体化する。意味評価にはIris/REPAと独立した評価器を併用し、画像例で被写体・個数・配置・色・形状の崩れを確認する。DINO系を使う場合はIrisのREPA教師との重なりも記録する。

成果の判定は未使用画像における容量・忠実性・意味保存の関係とし、Irisの優位を前提にしない。候補Bや他モデルへの移行は、その結果と実測資源を見て選ぶ。この文書は計画であり、追加学習や新しい評価器の実行はまだ行っていない。
